## Problem and scope

The 2026-09-26 audit found 11 `readJsonBody` definitions and repeated `requireXContext` patterns, with no uniform request-size cap; error payloads vary, and deleted-user detection depends on message substring matching. Verify the current count before editing. Introduce a shared Pages Functions request boundary (middleware and/or focused helpers) for authentication context, D1 binding, bounded body parsing, typed errors and consistent `{code,error}` responses. Set explicit documented limits appropriate to JSON and CSV import endpoints, returning 413 before unbounded allocation; 400 for malformed JSON. Replace message-substring deleted-user detection with a typed code/class while preserving 410 semantics. Keep `/api/health` public and meaningful; signed-out protected APIs must still return 401.

Inventory every endpoint and its current response contract before consolidation. Preserve 401/403/404/409/410 distinctions, tenancy filters, idempotency, CORS behavior and frontend error rendering. Bring health responses through the shared JSON response helper without adding authentication or revealing private state. If a response-shape change is necessary, update every typed consumer and document compatibility; do not hide a breaking API change as refactor. PA-9 applies only if `App.tsx` feature code is edited; prefer not to edit it here.
