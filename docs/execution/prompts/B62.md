# B62 — Exact-term schedules for lump sum and monthly recurring calculators

C25. Same owner continuation as B61. Fixes the fractional-term schedule defect recorded as a residual in C24 for `lumpsum-mutual-fund` and the same defect found in the shared monthly recurring schedule. Baseline main `65feeef0bdd6d929c21f71e51ac1b4fc98c239de`.

**Source convention (inspected):** every engine below computes a fractional term exactly — lump sum `principal × (1 + rate)^years`; compound, SIP, step-up SIP, RD and NPS over `months = max(1, round(years × 12))`. The detail schedules instead use `scheduleYears = ceil(years)`: `singleDepositGrowthSchedule` steps whole years and `recurringGrowthSchedule` (non-APY path) runs `ceil(years) × 12` months. The HYSA APY path already uses exact months.

**Reproduced evidence (`evidence/C25/raw/baseline.json`, 1.5-year term, other inputs default):** lump sum headline ₹5,61,184.46 versus final schedule row "2" ₹5,83,200; RD and SIP ₹1,90,571.91 versus ₹2,59,331.90 (24 months, ₹2,40,000 deposited); step-up SIP ₹1,96,672.80 versus ₹2,71,781.82; compound interest $20,799.07 versus $24,695.47; NPS schedule corpus ₹2,59,331.90 versus a 18-month engine corpus. The table and CSV therefore contradict the headline for any non-whole-year term.

## Outcome and scope

| ID | Requirement |
|---|---|
| R1 | Lump sum: whole years then the exact remaining part year (same method as B60's deposit schedule); the last row equals the headline; a part-year row says the annual rate is applied for that fraction. Columns: "Growth this period", "Total growth", "Value" — market-linked growth, not deposit interest. |
| R2 | Monthly recurring schedule (compound, SIP, step-up SIP, RD, NPS): run exactly the engine's months; a final part-year row is labelled with the exact term in years (e.g. 1.5) and notes the number of months in that period; the last row equals the headline balance and total deposits. HYSA keeps its APY path. |
| R3 | Whole-year terms produce the same rows and values as baseline, except the lump-sum column labels (R1). RD schedule columns read "Deposits this period"/"Balance". |
| R4 | Table, chart-data table and the actual CSV agree with the headline. |

**Non-goals:** any engine/formula change, other schedule builders (EPF, PPF, savings goal, loans and the rest — survey recorded as residual), result objects, scenario vectors, model versions, analytics, schema, production.

**Files:** `calculatorStudios.ts`, focused tests; existing tests that pinned the old lump-sum labels are updated deliberately.
