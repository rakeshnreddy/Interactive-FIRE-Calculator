# B83 / C44 — Stage 1: Option A Split Financial Workbench & Above-the-Fold Visual Chart for Shared Studio Calculators (75 Routes)

## Context & Problem Statement

Following the accepted Option A Split Financial Workbench (`B81 / C42`) and `/unslop` redline (`B82 / C43`) on `/calculators/fire`, live inspection at `1440×900` across the **75 shared studio calculators** rendered by `CalculatorDetail` (`src/CalculatorLibrary.tsx`, `src/studios.css`) — e.g., `/calculators/mortgage`, `/calculators/401k`, `/calculators/sip`, `/calculators/emi` — revealed four systemic usability and visual defects:

1. **Double box-in-a-box inputs across all 75 studio routes:**
   - `:is(.field input, ...)` in `@layer workspace` (`src/workspace.css:590`) outranks `@layer studios` (`src/studios.css:834`), giving `<input>` inside `.calculator-input-control` an inner `1px` border and `44px` height inside the outer `.calculator-input-control` border.
2. **Oversized header + stacked `.estimate-customization` pushing core inputs and `View result` below the fold:**
   - `.calculator-detail > .calculator-library-heading` occupies `~254px`, and `.estimate-customization` occupies up to `~210px` (e.g., `/calculators/mortgage`), pushing the first input down to `y = 740px` and the bottom of `.calculator-input-panel` to `y = 1,270px – 1,473px` (370–570px below a `900px` desktop viewport).
   - Uneven multi-line helper texts misalign paired inputs vertically across rows in `.calculator-input-grid`.
3. **Interactive visual chart (`.calculator-visual-panel`) pushed completely below the fold:**
   - On the right-hand `.calculator-result-panel`, `.calculator-visual-panel` (the studio breakdown/comparison bar chart) sits below tall 2-column supporting metric cards, `.calculator-scope`, and `<VariantChips>`, starting at `y = 922px – 1,030px` (completely invisible at `1440×900` without scrolling).
4. **Wide legacy `table { min-width: 1040px; }` overflow inside `.calculator-breakdown-table-wrap` & left-aligned numeric cells in `.calculator-chart-table`:**
   - Compact 3–5 column studio schedules inherit legacy `min-width: 1040px`, creating unnecessary horizontal scrollbars inside the right-hand panel, and `.calculator-chart-table` left-aligns numeric columns.

## Requirements (`R1`–`R5`)

- **R1 (Global single-border `.calculator-input-control` & aligned 2-up studio input workbench):**
  - Scope `src/workspace.css:590,600` to direct-child `.field > input` (instead of `.field input`) so `.calculator-input-control input` never receives a second inner border across all 75 studio calculators (and dedicated planners), while standalone `.field > input` controls keep their border and focus ring.
  - Compact `.workspace:has(.calculator-detail)` (`min(1320px, ...)`), `.calculator-detail > .calculator-library-heading` (2-column header placing the `Explore the ... toolkit` backlink on the right on `>= 721px`), and `.calculator-detail-grid` (`minmax(440px, 500px) minmax(0, 1fr)` on `>= 1041px`, `1fr` on `<= 1040px`).
  - Quiet `.calculator-detail .estimate-customization` into a crisp single-row bottom-ruled jump bar with compact inline buttons (`min-height: 28px`) so the core inputs start near the top of the left workbench.
  - Align `.calculator-detail .calculator-input-grid` with `align-items: start` and compact `36px` `.calculator-input-control` boxes (`32px` borderless inner `input`), compact `.calculator-options-shell` summaries, and compact `.calculator-scenario-panel` tabs so core inputs + optional disclosures + `View result` sit above `900px` at `1440×900` on representative studio routes (`/calculators/mortgage`, `/calculators/401k`, `/calculators/sip`).
- **R2 (Above-the-fold result ledger & default-visible studio visual chart):**
  - Move `<CalculatorStudioVisual>` (`.calculator-visual-panel`) in `src/CalculatorLibrary.tsx` directly below `.calculator-result-metrics` (and any compact reconciliation strip) and above `<CalculatorScopeNotice>` and `<VariantChips>`, while preserving `.calculator-result-metric-primary` preceding `.calculator-variants`.
  - Use a 6-column smart metric grid inside `.calculator-detail .calculator-result-metrics` on `>= 601px` (`.calculator-result-metric-primary` spans `1 / -1`; supporting metrics span `3` for 2 or 4 supporting cards and `2` for 3 or 5+ supporting cards such as `/calculators/mortgage`) so zero orphan slots appear and supporting metrics stay compact.
  - Compact `.calculator-detail .calculator-result-panel`, `.calculator-result-state` (single-line strip), and `.calculator-studio-chart` (`12px` padding, `8px` row gap) so both the headline answer + supporting metrics AND `.calculator-visual-panel` are visible above the `900px` fold at `1440×900`.
- **R3 (Clean tabular schedule & chart-data tables):**
  - Override `.calculator-breakdown-table-wrap table { min-width: 0; width: 100%; }` in `src/studios.css` so compact schedules fit cleanly without forced `1040px` horizontal scrolling.
  - Right-align numeric columns in `.calculator-chart-table` (`:is(th, td):nth-child(2)`, `:nth-child(3):not(:last-child)` or numeric cells) while keeping category labels left-aligned.
- **R4 (Strict `/unslop`, multi-size responsiveness & hosted smoke verification):**
  - Maintain strict 4px spacing in `src/studios.css` (`src/CalculatorStudioUnslop.test.tsx`), radii `<= 12px`, weights `400/500/600`, WCAG 2.2 AA contrast `>= 4.5:1` (`src/UnslopFinalPolish.test.tsx`), and `0px` horizontal overflow across `1440px`, `1200px`, `1041px`, `900px`, `768px`, `560px`, `390px`, and `320px`.
  - Extend `scripts/smoke/c41-unslop-final-polish.mjs` to assert above-the-fold split-workbench geometry (`sideBySide === true`, `.calculator-visual-panel` top `< 900px`, and `0` inner-border double-box inputs) on `/calculators/mortgage` at `1440×900` in both light and dark modes.
- **R5 (Zero formula, routing, or schema mutations):**
  - Do not modify `src/lib/seoCalculators.ts`, `src/lib/fire.ts`, financial formulas, `calculatorModelVersions`, `worker/`, `functions/`, or `migrations/`.
