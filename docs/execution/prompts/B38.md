## Problem and scope

The audit observed generic server HTML for public calculators, unknown paths returning 200/indexable, Clerk code/network on public pages, and large client bundles. Verify each baseline on the current build. Use build-time prerender or static metadata injection from `src/lib/routeMetadata.ts` so sampled calculator HTML has route-specific title, description, canonical and minimal truthful content. Preserve all stable calculator URLs. Return a genuine 404 with `noindex` for unknown paths without breaking SPA navigation or Pages Functions API routing. Load Clerk only on an authenticated route or explicit sign-in intent; public calculators must remain useful before auth download. Split route code with `React.lazy` or equivalent so the main raw JS chunk is below 250 KB on the final build, with no Vite size warning. Measure actual transfer and interactions, not only a bundle file name.

Add `public/_headers` (or provider-equivalent) with tested CSP, HSTS, `X-Content-Type-Options`, `Referrer-Policy` and `frame-ancestors`. Derive CSP from actual public and signed-in requests; avoid `unsafe-eval`/broad wildcard unless a documented provider requirement and compensating control exist. Verify Clerk, functions and previews work under headers. PA-9 applies if touching an `App.tsx` feature region; extract it or document an approved narrow opt-out. No new SSR framework, content rewrite or production launch.
