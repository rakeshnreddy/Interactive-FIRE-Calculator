# B70 — Contrast-checked design foundation and application shell

C31. Registered 2026-10-26 before implementation, after B68/C30. Direction: Luminous Observatory from [the preserved audit](../../calculator-excellence/ANALYSIS_2026-10-18.md). The owner grants visual authority and asks for stepwise verified releases. This registration approves no fabricated contrast, screenshot or performance evidence.

## Outcome and bounded scope

| ID | Acceptance requirement |
|---|---|
| R1 | Compute actual light/dark OKLCH tokens and measure rendered foreground/background pairs, including transparency compositing. Target WCAG 2.2 AA text and control/focus contrast; preserve solid, legible tabular financial numbers. Record exact pairs and measured ratios. |
| R2 | Establish one token owner and an explicit stylesheet/cascade-layer architecture. Inventory the unlayered legacy rules, migrate conflicting shell rules and prove the new layers win as intended. Do not append another uncontrolled override stack. |
| R3 | Redesign navigation and footer across desktop/mobile, signed-out and auth-unavailable states. Preserve every route, functional navigation, keyboard order, visible focus, mobile menu semantics and existing auth boundaries. |
| R4 | Reproduce and fix the invisible eyebrow foreground/background pairs. Verify every affected page family in both themes; the audit's 22-route count must be measured, not assumed. |
| R5 | Add supported route transitions with a safe unsupported-browser path and a reduced-motion path. Navigation, focus, history and result-reveal behaviour must work when transitions are disabled or interrupted. |
| R6 | Verify 1440/768/390/320 in both themes, keyboard navigation, reduced motion/transparency and reflow. No page overflow at 320px. Compare performance/layout and JS/CSS size to an observed baseline; no invented measurements or accessibility-conformance claim. |
| R7 | Update the dated design direction in `DESIGN.md`, explaining superseded rules and migration boundaries. Publish a reviewable before/after board or evidence artifact and candidate/beta links. |

**Likely files (confirm first):** `src/vivid-theme.css`, shell rules in `src/styles.css`, app shell/navigation/footer components, routing helpers and focused UI/style checks. Use matching gstack design/QA skills during implementation.

**Non-goals:** calculator arithmetic/model/snapshot changes, all home/library/template/chart/workspace redesigns, wholesale removal of legacy CSS (B76), new financial advice, auth/provider changes, production, new dependencies without justification. Do not alter `src/lib/fire.ts`.

**Release:** the same full suite, exact-head CI, isolated candidate verification, 84-route smoke, real-browser evidence and verified stable-beta promotion as B68. Raw artifacts remain ignored; commit compact hashes and at most the permitted selected screenshots. Merge after final documentation CI and confirm main CI. Retain a compatible rollback source.

**Dependencies:** B68 and accepted C30. B70 remains pending at registration. Other visual stages and B69 remain proposals until separately registered; their audit IDs do not imply acceptance.
