# B82 / C43 — FIRE Calculator `/unslop` Redline: Optional Refinements, Structured Repeat Rows & Output Data Presentation

## Context & Problem Statement

Following `B81 / C42` (Option A Split Financial Workbench on `/calculators/fire`), visual inspection of `/calculators/fire` with `#fire-optional-refinements` expanded and across secondary output views (`Table`, `Compare`, `Plan health`, and `Save and move plans`) revealed four usability and data-presentation defects:

1. **Overlapping inputs inside `Optional refinements` (`#fire-optional-refinements`):**
   - Because `#fire-optional-refinements` sits inside `.fire-workbench-inputs` (`450–500px` wide at `>= 1041px`), the legacy `.planner-grid` rule (`grid-template-columns: repeat(2, minmax(0, 1fr))` on `> 1040px`) splits the `474px` inner container into two `227px` columns.
   - Inside those narrow panels, `.repeat-row` (`367px` scrollWidth), `.event-row` (`461px` scrollWidth), and `.recurring-row` (`672px` scrollWidth) overflow horizontally and collide across neighboring panels and into the right-hand output stage.
   - At `<= 720px`, `.repeat-row` collapses to `1fr`, stretching the `.row-number` badge (`1`, `2`) into a full-width bar and stacking every numeric field vertically.
2. **`Year-by-year cash flow` Table View horizontal clipping & left-aligned numbers:**
   - Legacy `table { min-width: 1040px; }` forces the 11-column cash-flow table to overflow the `772px` right-hand output column on desktop, clipping `Return`, `Inflation`, and `End` balance behind horizontal scroll, while numeric columns remain left-aligned and the table stretches the page height by ~1,400px.
3. **`Plan health` 4-column grid orphan slot & `Compare` scenario card density:**
   - `.health-grid` hardcodes `repeat(4, minmax(0, 1fr))`, leaving an empty 25% right-hand gap when 3 plan checks render.
   - `#compare .scenario-card` stacks 5 raw `<small>` lines and 4 `44px`-tall shift inputs without ledger separation, and squeezes 3 cards across `768px` tablet viewports (`225px` per card).
4. **Competing `.estimate-customization` box chrome:**
   - `.estimate-customization` at the top of `.fire-workbench-inputs` renders a heavy bordered box competing with the primary segmented controls and the already-visible `Optional refinements` summary below.

## Requirements (`R1`–`R5`)

- **R1 (Non-overlapping 1-column `.planner-grid` & structured 6-column repeat cards in `#fire-optional-refinements`):**
  - Force `.fire-workbench-inputs .advanced-shell .planner-grid` to `grid-template-columns: minmax(0, 1fr)` at all viewport widths so every refinement section (`Market periods`, `Retirement model options`, `One-off events`, `Recurring income streams`, `Recurring spending phases`) receives the full width of the input workbench.
  - Restyle `.fire-workbench-inputs .advanced-shell .panel` as compact inset ledger groups (`padding: 12px`, `border-radius: 8px`, `background: var(--color-surface-inset)`).
  - **Market periods (`.period-list .repeat-row`):** Use `grid-template-columns: 32px repeat(3, minmax(0, 1fr)) 32px` (`32×32px` `.row-number` badge, `Years`, `Return`, `Inflation`, `32×32px` `.row-action` remove button) with `32px` compact inputs (`min-width: 0`) so all 5 items fit on one horizontal line inside `>= 381px` with `scrollWidth === clientWidth`, and wrap cleanly on `<= 380px` without stretching `.row-number` full-width.
  - **One-off events (`.event-row`):** Use a 6-column structured card (`grid-template-columns: repeat(6, minmax(0, 1fr))`): Row 1 has `Label` (`span 5`) + `.row-action` remove button (`span 1`, `justify-self: end`); Row 2 has `Year` (`span 2`) + `Amount` (`span 4`).
  - **Recurring income streams & spending phases (`.recurring-row`):** Use a 6-column structured card (`grid-template-columns: repeat(6, minmax(0, 1fr))`): Row 1 has `Label` (`span 5`) + `.row-action` remove button (`span 1`, `justify-self: end`); Row 2 has `Start` (`span 2`), `End` (`span 2`), and `Annual` (`span 2`); Row 3 has `Growth` (`Inflates | Fixed` segmented control, `1 / -1`) as an inline horizontal bar.
- **R2 (Right-aligned tabular ledger table in `#results`):**
  - Scope `#results .table-wrap` to `max-height: 360px; overflow: auto;` with sticky `thead th` headers (`position: sticky; top: 0; z-index: 1;`), `min-width: 640px` on `#results table` (fitting all 11 columns inside the `772px` desktop output stage with zero horizontal scrollbar at `1440×900`), compact `8px` cell padding, and right-aligned tabular numerals on columns `3..11` (`th:nth-child(n+3), td:nth-child(n+3) { text-align: right; }`).
- **R3 (Refined Hero Result, Compare cards, Plan Health grid & quiet customization header):**
  - Quiet `.fire-workbench-inputs .estimate-customization` into a subtle borderless/bottom-ruled header strip so it does not compete with `Planning question` / `Currency`.
  - Format `.fire-workbench-outputs .hero-result .fire-retirement-estimate` inside a clean inset ledger callout (`padding: 8px 12px`, `border-radius: 8px`, `background: var(--color-surface-inset)`).
  - Switch `.fire-workbench-outputs .health-grid` to `grid-template-columns: repeat(auto-fit, minmax(200px, 1fr))` so 1, 2, or 3 plan health cards fill the row without a blank 4th column.
  - Style `#compare .comparison-grid` as `repeat(3, minmax(0, 1fr))` on `>= 900px` and `minmax(0, 1fr)` on `< 900px`, with compact `32px` inputs, ruled `<small>` metric dividers, and tabular numerals inside `#compare .scenario-card`.
  - When the user clicks the `Inputs` (`'planner'`) tab in `.result-tabs-panel`, automatically open `#fire-optional-refinements` so advanced inputs are immediately revealed.
- **R4 (Strict `/unslop` & multi-viewport resize verification):**
  - Keep all spacing values in `src/workspace.css` on the 4px grid (`src/UnslopStageB.test.tsx`), all radii `<= 12px` and font weights in `400/500/600` (`src/UnslopFinalPolish.test.tsx`), and verify `scrollWidth <= clientWidth` for every `.repeat-row`, `.event-row`, and `.recurring-row` across `1440px`, `1200px`, `1041px`, `900px`, `768px`, `560px`, `390px`, and `320px`.
- **R5 (Zero formula or schema mutations):**
  - Do not touch `src/lib/fire.ts`, financial calculation formulas, `calculatorModelVersions`, `worker/`, `functions/`, or `migrations/`.
