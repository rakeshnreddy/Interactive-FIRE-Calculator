## User problem and explicit decisions

Fresh FIRE plans currently initialize return/inflation at 0% and the page calculates a portfolio target without an accumulation path. The owner chose OD-1: **return and inflation start empty and required; no result until each is entered or explicit example values are applied**. A deliberate typed 0% is valid. Provide non-prefilled, cited explanatory hints and a distinct “Use example values” action. The homepage example uses 7% return and 2.5% inflation (`src/lib/heroExample.ts`); these may be presented as illustrative, not mislabeled historical averages. Research and cite primary sources before making any historical performance claim. Show the user's actual chosen rates adjacent to the headline result. B35's no-injected-equity/house/Social-Security/healthcare-cash-flow rule remains.

OD-2 permits **one additive pure accumulation function** with current age, current portfolio, annual savings and optional savings growth that estimates the earliest age at which the modeled portfolio meets the stated retirement target. Specify annual deposit timing, inflation adjustment, horizon and stopping condition in a written formula contract. Existing drawdown functions and their golden outputs must remain behaviorally unchanged. Use at least five independent source/formula goldens: a normal case, explicit 0% rates, already financially independent, never reaches target within horizon, and increasing savings. Explain nominal versus real units, sensitivity and uncertainty; never promise an outcome.

## Interaction and data contract

If persistence schema changes, add a model-version field and additive migration with owner approval before remote application; test a pre-B36 record and explicit rollback. No automatic rewriting of historical plans.
- Apply PA-9: move the touched FIRE feature region out of `App.tsx` into a focused component, unless you document a narrow opt-out for Astra before coding. Do not rewrite unrelated panels.
