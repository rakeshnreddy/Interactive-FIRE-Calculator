## Acceptance

- R1: Replace unanchored substring matching in `adjustInput` (`src/lib/calculatorStudios.ts`) with word-bounded and key-aware classification so `"current"` (`cur-rent` in `Current savings`, `Current 401(k)`, `Current loan balance`, `Current balance`, `Current mortgage balance`, `Current portfolio`) never matches `rent`, and `key === 'income'` (`Annual taxable income before deductions` on `income-tax-india`) or `key === 'principal'` (`Pre-tax amount` on `gst`, `Today cost` on `inflation`) is never misclassified as an expense/tax because of label words `"taxable"`, `"Pre-tax"`, or `"cost"`. Hold statutory/fixed parameters and fixed targets constant across scenarios (`periods` on `paycheck`, `metroPercent` on `hra-exemption`, `annuityPercent` on `nps`, `annualIncome` on `retirement`, `target` on `sip-goal` and `savings-goal`, and `principal` on `inflation`).
- R2: Ensure directional truthfulness across Loan, Debt, Tax, Retirement, and Insurance scenarios (`RINC-01`, `RINC-10`, `LH-04`, `GGS-03`, `TAX-02`, `DEBT-05`, `CBS-03`):
  - In Debt Payoff Studio and Loan & Home Studio, borrowing/debt principal and balances (`balance`, `principal`, `homePrice`, `balanceOne`, `balanceTwo`) must not shrink in `Conservative` or grow in `Optimistic` in ways that make `Conservative` look cheaper or faster than `Base`; on rate-spread, prepayment, recast, balance-transfer, and snowball/avalanche comparison routes (`mortgage-refinance`, `home-loan-balance-transfer-india`, `mortgage-points`, `home-loan-prepayment`, `home-loan-foreclosure`, `mortgage-recast`, `balance-transfer`, `debt-snowball-avalanche`), hold baseline debt principal/rate fixed or perturb rate-spread/extra-payment inputs so `Conservative` represents the tougher/lower-savings case and `Optimistic` represents the stronger/higher-savings case.
  - On `roth-vs-traditional-ira`, do not invert `rate` (`Annual return`) via `riskierRateStudios`, and perturb `futureTaxRate` relative to `currentTaxRate` so scenarios test retirement vs current tax-rate spread (`TAX-02`); on `hra-exemption`, ensure `Optimistic` never reduces the HRA exemption below `Base` or `Conservative`.
  - On `life-insurance-needs` (`formula === 'insurance'`), `Conservative` ("larger coverage needs") increases `years`/`debts` and decreases `savings` (raising recommended coverage above `Base`), while `Optimistic` ("better coverage progress") decreases `years`/`debts` and increases `savings` (lowering recommended coverage below `Base`) (`CBS-03`).
  - On `social-security-break-even` and `rmd` (`RINC-10`), perturb `full` (`Later monthly benefit`) on `social-security-break-even` and `divisor` on `rmd` with truthful scenario descriptions that never claim "growth or contribution assumptions".
  - Cleanly round scaled float values (`Number(val.toFixed(6))`) on routes other than the 4 baseline float-pinned routes (`cd`, `rd`, `sip`, `step-up-sip`) so IEEE-754 float tails (`112000.00000000001`, `110000.00000000001`) never leak into `scenarios` or `buildCalculatorSummaryCsv`.
- R3: Return Analysis scenario labels, neutral chart tones, short-term fractional steps, and signed ROI loss perturbation (`RET-01`, `RET-03`, `RET-06`):
  - Include `xirr` alongside `investment-return` and `cagr` in neutral scenario labels (`'Case A'`, `'Your inputs'`, `'Case B'`) and sensitivity-check scenario descriptions; in `comparisonChart`, use `'neutral'` tone for `investment-return`, `cagr`, and `xirr` instead of hardcoding `'warning'` for `conservative` and `'positive'` for `optimistic`.
  - When `years <= 1` (`RET-03`), use fractional steps (`0.25` years) with a positive floor (`Math.max(input.min || 0.25, ...)`) in `adjustInput` and `inputImpact` so `years` never steps down to `0`.
  - On `roi` (`RET-06`), adjust signed `gain` using `value + direction * Math.abs(value) * 0.08` so `Conservative` worsens a negative gain (`-5000 -> -5400`) and `Optimistic` improves it (`-5000 -> -4600`), and when `gain < 0`, `cost` does not inflate in `Conservative` to dilute the percentage loss.
- R4: In `changedInputsLabel` (`src/CalculatorLibrary.tsx`), list all changed inputs for each scenario card instead of truncating with `.slice(0, 3)`.
- R5: Bidirectional, piecewise-cap-aware, and secondary-metric-aware sensitivity drivers (`inputImpact` in `src/lib/calculatorEngagement.ts`) (`LH-08`, `RINC-04`, `RINC-13`, `GGS-07`, `TAX-07`, `DEBT-05`, `RET-06`):
  - When `Math.abs(higherOutput - baseOutput) <= 1e-9` at an upper input/formula cap (`ppf` `annual = 150000`, `mortgage-affordability` `maxDti = 28%`, `home-loan-foreclosure` `prepayment = 3500000`), derive `direction` from `baseOutput - lowerOutput` so `direction` is `'raises'`/`'lowers'` instead of `'unchanged'` whenever `magnitude > 0`.
  - On `ppf` (`formula === 'ppf'`, `input.key === 'years'`), use whole-year integer steps (`Math.max(1, Math.round(change))`) so `inputImpact` never evaluates invalid fractional PPF years (`13.5` / `16.5`).
  - For zero-default currency inputs (`current === 0 && input.defaultValue === 0`, such as `extraMonthlyPayment`, `extraAnnualPayment`, `annualTopUp`, `deductions`, `current`), scale `change` from the calculator's positive currency inputs (`Math.max(100, Math.round(referenceCurrency * 0.05))`) instead of `1` (`$1` / `₹1`), so optional extra payments, top-ups, and deductions produce meaningful non-zero impacts that never round to `"up to $0"` / `"up to ₹0"`.
  - For `<5%` positive percentage inputs (`input.type === 'percent'` and `Math.abs(current) > 0`), use proportional perturbation `Math.abs(current) * 0.1` instead of a flat `0.5` floor so low-rate sensitivities stay proportional (`±10%` relative).
  - When an input is invariant on `result.metrics[0]` (`magnitude <= 1e-9`), inspect `baseResult.metrics.slice(1)` for the first supporting numeric metric (`currency`, `percent`, `number`, `years`, `months`) that changes across `lowerResult`/`higherResult`, compute `baseOutput`/`lowerOutput`/`higherOutput`/`magnitude`/`direction` from that supporting metric, and name that metric in `summary`.
  - On `roi` when `gain < 0` and `input.key === 'cost'`, clarify the sensitivity summary so increasing cost on a fixed dollar loss is described accurately as spreading the fixed loss across a larger cost base.
- R6: Preserve all existing pinned scenario vectors (`fd`, `cd`, `rd`, `lumpsum-mutual-fund`, `sip`, `step-up-sip`, `ppf`, `investment-return`, `cagr`), `mortgage` scenario labels (`Conservative`, `Base`, `Optimistic`), `buildCalculatorInputImpacts` length invariants (`calculator.inputs.length` for all calculators except `vehicle-cost`), and all 14 existing `calculatorModelVersions` entries and slug mappings.
