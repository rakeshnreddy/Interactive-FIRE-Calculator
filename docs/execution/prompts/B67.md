# B67 — Market-growth presentation for lump sum, SIP and step-up SIP

C29. Owner: "ok do that" (route-specific helpers for high-traffic routes, C28 handoff). Baseline main `e7411660289835e09ef4a564e4503309c25c8a36`. `compound-interest` is excluded: it already has a dedicated experience that states rate basis and contribution timing.

**Source convention (inspected in `seoCalculators.ts`):**
- `lumpsum` (`lumpsum-mutual-fund`) shares the FD case: `principal × (1 + rate)^years` — the entered return compounded once a year (equivalent to an annualised/CAGR return), result labelled "Maturity value / Estimated interest".
- `sip` (`sip`, `step-up-sip`): `months = termMonths(years)`; each month `value = value × (1 + rate/12) + instalment` — instalments at the end of each month, the yearly return divided by 12 and compounded monthly; the step-up multiplies the instalment once a year from month 13; an optional extra amount is added after every 12th instalment. A rate entered here compounds to more than the same CAGR (12% ÷ 12 monthly = 12.68% a year, Decimal 1.12682503).

**Reproduced evidence (`evidence/C29/raw/baseline.json`):** lump sum calls a market-linked fund "Maturity value" and "Estimated interest"; its guidance says "Evaluate required regular contributions against your monthly budget" though it has no contributions; all three use "Annual return / rate", Conservative/Base/Optimistic labels for what-ifs that also change the amount invested, "contribution or return assumptions" lens copy, and state neither timing, compounding basis nor that expenses/exit loads/tax are not deducted. No page says a constant return is not a forecast.
