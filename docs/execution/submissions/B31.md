## How the matrix was run

Two scenario modules for the shared PA-1 runner (no bespoke harness), run against the immutable preview with provider-verified preflight and fail-closed cleanup:

- `scripts/smoke/b31-visual.mjs` — viewport matrix, keyboard and focus, reduced motion / reduced transparency / forced colours, contrast measured from effective pairs, state coverage, three-run lab performance, console and CSP cleanliness.
- `scripts/smoke/b31-zoom.mjs` with the runner's new `--zoom 200` — **real Chrome per-host zoom** (a seeded profile preference in a persistent context, not device metrics or CSS zoom), verified by `innerWidth = outerWidth / 2` and `devicePixelRatio` doubling. Public and signed-in routes in both themes, long values and errors at 200%. Anonymous pages get their own zoomed profile (the independent review found the first version reused the signed-in profile); the scenario asserts the anonymous page has no session and no Clerk. Profiles are removed after the run; `--zoom` refuses two-tenant scenarios.
- Screenshots land in `docs/execution/evidence/B31/raw/` (ignored by Git, `88` files on this machine); the runner reports are committed: [`b31-visual-f85c6dd.json`](../evidence/B31/b31-visual-f85c6dd.json), [`b31-zoom-f85c6dd.json`](../evidence/B31/b31-zoom-f85c6dd.json).

## Defects the sweep found and fixed (each re-verified on the final candidate)

1. Input controls' three-column grid squeezed the unit suffix to 15px when there was no currency prefix (FIRE at 320px) → flex layout (`b9aa64a`).
2. Privacy band's sign-in button forced a 157px icon column at 390px, leaving 99px for the heading → button placed under the text; single column ≤ 560px (`b9aa64a`).
3. Footer three-column grid left the tagline 40px wide at 768px → link list on its own row below desktop (`b9aa64a`).
4. Primary teal `#0b7c6c` on soft tints measured 3.8–4.2:1 (badges, pills, active nav link) → `--color-primary-ink` (`df9a764`).
5. Gradient eyebrow text's blue stop measured 4.1:1 on the light canvas → `--text-gradient` (`df9a764`).
6. Light muted text `#55697c` measured 4.44:1 on panel surfaces → `#465a6e` (`dcfc377`).
7. Three hidden file inputs (plan JSON, balances CSV, transactions CSV) had no accessible name → `aria-label` (`5531694`, `dcfc377`).
8. Help dots (18px), breadcrumb buttons (23px), footer links (22px), toolkit backlinks (20px) and summaries (18px) were under the 24px target minimum → min sizes (`7f67cfa`).
9. Every page load logged a 404 for `/favicon.ico` → SVG/ICO/apple-touch icons linked (`7f67cfa`).
10. Runner: an in-flight Clerk token refresh cancelled by navigation crashed the process before cleanup → handled (`b9aa64a`).
11. Runner `--zoom`: the anonymous page shared the tenant's profile and profiles were left on disk → isolated profiles, removed at the end, two-tenant scenarios refused (`f85c6dd`, from the independent review).
12. Toolkit and footer anchor links stayed on the homepage → fragments route and scroll (`f85c6dd`, from the independent review).

## Actual screen-reader pass (VoiceOver, 2026-09-28) — B31 reader gate

Run per [B31_READER_PROMPT.md](../B31_READER_PROMPT.md) with the shared runner: `node scripts/hosted_smoke.mjs … --scenario b31-reader --headed` against preview `https://d0d235df.interactive-fire-calculator.pages.dev` (deployment `d0d235df-3d54-4d7d-9f88-745ff9f6f71b`, code `2277b80`). Report: [b31-reader-2277b80.json](../evidence/B31/b31-reader-2277b80.json) (the `announcement-matrix` stage holds every step's expected pattern and **VoiceOver's actual spoken phrase**, read back from VoiceOver itself via `content of last phrase`). Synthetic tenant, cleanup verified.

- **Reader and browser:** VoiceOver on macOS 26.6.2, Google Chrome 154.0.8037.58 (visible window), owner-enabled "Allow VoiceOver to be controlled with AppleScript".
- **Coverage (41 steps, 41 matched on the final run):** homepage skip link (first Tab stop; Enter moves focus into `#main-content`, verified in the DOM), heading levels 1/2, calculator search field; FIRE heading, input labels with their help text, "Required; 0 is allowed", blocked Calculate read as *"Calculate … Enter expected return and inflation … dimmed button"*, invalid return error (*"Use a return between -50% and 50% a year."*), example values, the answer announced as *"Result updated. FIRE number $1.3M. Retire at about age 48."*, the "Savings path by age" disclosure (collapsed → expanded) and its table (*"Age … table 3 columns, 4 rows"*); mortgage heading, rate field, metric help (collapsed → expanded), scenario tab (*"Conservative $1,985 tab, 1 of 3"*), amortization schedule disclosure and table (*"Payment # … table 8 columns, 361 rows"*); signed-in level-1 headings on dashboard, plans, reports, transactions and settings; Workspace menu (collapsed → expanded → first link → Escape returns focus, collapsed); analytics consent (*"Product analytics is off unchecked checkbox"*); deletion confirmation with its described-by warning; at 390px the navigation button (collapsed/expanded/Escape) and the theme switch in both directions.
- **Defects the reader found and fixed (`2277b80`, regression tests in `src/fireRetirement.test.tsx`):**
  1. The FIRE answer was never announced after Calculate (VoiceOver said only *"You are currently on a button"*). Added a polite live region that announces the headline answer after each calculation.
  2. The blocked Calculate button was `disabled`, so it could not be focused and its reason could not be heard. It is now `aria-disabled` (focusable, described by the reason, pressing it does nothing).
  First run 27/37 matched; the remaining misses were harness issues (focus not reset before the first Tab, result tables inside collapsed disclosures, heading expectations, VoiceOver still reading a 361-row table), fixed in the scenario and rerun.
- **Limitations, stated plainly:** (a) navigation moved **keyboard focus** (Tab, and programmatic focus to headings and table headers); macOS did not apply the keystroke permission to this running session, so VoiceOver's own key chords (VO-Command-H rotor, VO-arrows) were not exercised — the scenario uses them automatically when permitted. (b) The search "no matches" step only confirmed the typing echo; the empty-state text sits in a polite live region but was not heard within the settle window, so that announcement is **not verified**. (c) NVDA/Windows not tested. (d) Theme changes do not alter announced meaning; the theme control was checked in both directions. No WCAG conformance claim.
