## Changed behavior

- **`LH-02` — Sub-1-year loan term parity and `<= 0` term rejection (`src/lib/seoCalculators.ts`, `src/lib/calculatorStudios.ts`, `src/lib/calculatorInputState.ts`):** Removed hidden `Math.max(1, years)` clamps on `loan-comparison`, `rent-buy`, and all 12 loan schedule builders in `src/lib/calculatorStudios.ts` (`loanAmortizationSchedule`, `aprBreakdownSchedule`, `balloonLoanSchedule`, `biweeklyLoanSchedule`, `fhaConventionalComparisonSchedule`, `loanComparisonSchedule`, `loanPrepaymentSchedule`, `mortgageRecastSchedule`, `armPaymentSchedule`, `pointsBreakEvenSchedule`, `refinanceComparisonSchedule`, `rentBuySchedule`) in favor of `termMonths(...) / 12`. Aligned `flat-rate-loan` interest and `armPaymentSchedule` final-row fractional year + `'First adjustment'` note with whole-month execution, and rejected `years <= 0`, `compareYears <= 0`, and `loanYears <= 0` across all 18 borrowing formulas (`positiveTermFormulas`).
- **`LH-07` — Cross-field Loan & Home validation & scenario boundary preservation (`src/lib/calculatorInputState.ts`, `src/lib/calculatorStudios.ts`, `src/lib/seoCalculators.ts`):** Enforced `downPayment < homePrice` and `homePrice > 0` on financed loan routes (`fha-loan`, `va-loan`, `fha-vs-conventional`) and `downPayment <= homePrice` on purchase-comparison routes (`closing-costs`, `pmi`, `rent-vs-buy`, etc.); rejected `principal <= 0` and `closingCosts >= principal` on `apr` while lowering `approximateApr`'s `netProceeds` clamp floor to `1e-9`; rejected `fixedYears <= 0`, `< 1 month`, and month-rounded `fixedYears >= years` on `arm-mortgage`; rejected `balloonYears > years` and positive sub-1-month `balloonYears` on `balloon-loan` while preserving month-0 immediate balloon (`0`); and updated `buildScenarioValues` + `adjustInput` so generated scenarios remain valid across boundary inputs.
- **`RET-02` — Return Analysis zero-denominator boundaries (`src/lib/calculatorInputState.ts`, `src/lib/calculatorStudios.ts`):** Required `initial > 0` and `years > 0` on `investment-return` and `cagr`, `years > 0` and `(initial > 0 || monthly > 0)` on `xirr`, and `rate > 0` on `rule-of-72`; guarded `investmentReturnSchedule`, `xirrApproximationSchedule` (`termMonths` alignment), and `doublingSchedule` to return `null` on invalid boundary inputs while keeping direct `calculateSeoCalculator` calls finite and preserving proportional `rule-72` Conservative scenario ordering.
- **`RINC-04` (`ppf`), `RINC-05` (`rmd`), `TAX-03` (`paycheck`), `RINC-15` (`retirement`) (`src/lib/seoCalculators.ts`, `src/lib/calculatorStudios.ts`, `src/lib/calculatorInputState.ts`):** Set `ppf` `annual` `min: 500` and `years` `min: 1, step: 1` (preserving the whole-financial-year message for fractional inputs like `15.5`); set `rmd` `divisor` `min: 1, max: 100, step: 0.1` and aligned engine/schedule `Math.max(1, divisor)`; set `paycheck` `periods` `min: 1, max: 365, step: 1` with integer validation and `Math.max(1, Math.round(periods))` engine/schedule alignment; set `retirement` `currentAge`/`retirementAge` `min: 0, max: 120, step: 1` and rejected `retirementAge < currentAge` while keeping `retirementAge === currentAge` (`B68`) and `60.125` history compatibility intact.
- **Automated tests & C34 hosted smoke (`src/CalculatorBoundaryValidation.test.tsx`, `scripts/smoke/c34-boundary-validation.mjs`):** Added 51 red-first unit + live `CalculatorLibrary` UI validation tests in `src/CalculatorBoundaryValidation.test.tsx` and added `scripts/smoke/c34-boundary-validation.mjs` for `scripts/hosted_smoke.mjs` checking 104 viewport/theme cases across 13 routes and 12 interactive boundary/sub-1-year DOM checks.
