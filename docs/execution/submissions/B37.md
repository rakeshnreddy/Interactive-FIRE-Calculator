## 2. Evidence Manifest & Provenance: First-Add vs. Latest-Content Revisions

### First-Add and Content Revision Architecture
`scripts/generate_evidence_manifest.mjs` satisfies the dual-revision requirement:
1. **First-Add Provenance (`added_commit`, `added_sha256`, `added_bytes`)**: Computed using `git log --diff-filter=A --format=%H -1 -- <path>`. Proves the exact commit that introduced the path into the repository.
2. **Latest Content Revision (`content_commit`, `sha256`, `bytes`)**: Computed using `git log -1 --format=%H -- <path>`. Proves the latest content revision.
3. **Retrieval Command**: Explicitly provided for accepted review consumption: `git show <content_commit>:<path>`.
4. **Fail-Closed Offline Verification**: `node scripts/generate_evidence_manifest.mjs --verify` reads directly from the Git object database using `git show` and `git cat-file`. It verifies that:
   - The recorded `added_commit` is the true first-add commit (`--diff-filter=A`).
   - The bytes retrieved from `git show <added_commit>:<path>` match `added_sha256` and `added_bytes`.
   - The bytes retrieved from `git show <content_commit>:<path>` match `sha256` and `bytes`.
   - If `content_commit` differs from `added_commit`, it verifies `content_commit` is indeed the latest modifying commit.
