# B41 submission — shared API boundary

Status: `ready_for_review` (Claude, owner takeover 2026-09-26; Codex accepts).
Code: `b4c7919`. Preview: `https://dc89f78e.interactive-fire-calculator.pages.dev` (deployment `dc89f78e-9755-4e2e-93c4-c5e77c7717f8`, preview D1).

## Inventory before the change
- 11 identical `readJsonBody` copies: 5 in `_lib` and 6 in `api/`.
- No request-size limit anywhere, including CSV imports.
- 503 responses returned `{authConfigured:false}` / `{databaseConfigured:false}`.
- `health.ts` built its own Response.
- Deleted-user detection used `message.includes('USER_DELETED'|'ACCOUNT_DELETED')` in 4 places.

## Changes
- **`functions/api/_middleware.ts`** (runs for every `/api` route, so no endpoint can bypass it):
  - **Body caps:** 256 KB for JSON and 1 MB for `/api/imports/*`. That covers the 500-row import limit with plenty of headroom.
  - **413 before buffering:** a declared `content-length` over the cap gets 413 `PAYLOAD_TOO_LARGE` immediately. Streamed bodies are counted while reading and cancelled once past the cap, with no unbounded allocation.
  - **GET/HEAD/OPTIONS:** untouched.
  - **Uncaught errors:** become `{code:"INTERNAL_ERROR", error}` without leaking the internal message.
  - **Legacy `{error}` bodies:** gain a status-derived `code` (for example `NOT_FOUND`), with every existing field kept. This is additive and compatible; the frontend reads `error`, which is unchanged.
- **Shared `readJsonBody`** in `_lib/http.ts`; all 11 copies removed. Malformed JSON still returns 400 with each parser's own validation message.
- **Typed deleted-user errors:**
  - `isDeletedUserTriggerError` recognises only the exact trigger contract from migration 0006 (`USER_DELETED: Cannot insert|update <table> for deleted user`).
  - `toTypedDatabaseError` turns that into `UserDeletedError`, and `handleApiError` returns 410 only for the typed class.
  - Forged text such as `Invalid name "USER_DELETED"` now returns 500, not 410.
- **Shared JSON helpers** for the 503 configuration responses (`AUTH_NOT_CONFIGURED` and `DATABASE_NOT_CONFIGURED`, keeping the old boolean flags) and for `/api/health`, which stays public.
