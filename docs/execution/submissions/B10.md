## Problem and change

User problem:
Users navigating from dashboard follow-ups or saved planning lists had no mechanism to deep-link directly to a specific saved version of a FIRE plan. Attempting to review an earlier plan revision forced users to manually reconstruct previous inputs. Furthermore, navigating away while modifying plan inputs silently discarded changes without confirmation. Nonexistent plan IDs or out-of-range version numbers lacked controlled, user-facing error states.

Implementation:
1. **Safe Route & Query Parsing**:
   - In `src/App.tsx` and `src/lib/navigation.ts`, wired URL search parameters `planId` and `version` on the `/plans` route (`/plans?planId=${planId}&version=${version}`).
   - Ensured URLs remain opaque and privacy-preserving: only opaque UUID plan IDs and integer version numbers are included. Zero financial figures, balances, or personal assumptions are placed in query strings.
2. **Exact Version State Restoration**:
   - In `src/PlanningWorkspace.tsx`, wired the `activePlanVersionNumber` prop and version switching logic.
   - When navigated via deep link to an earlier version (e.g. Version 1 of a plan revised to Version 2), `PlanningWorkspace` restores that version's inputs and calculation results.
   - Rendered `.historical-version-banner` with clear context: `"Viewing historical decision Version 1"`.
   - Verified that Version 2 revised inputs do not leak into the Version 1 view.
3. **Unsaved Changes Protection**:
   - In `src/PlanningWorkspace.tsx`, tracked dirty state by comparing current inputs against the loaded baseline.
   - Attempting navigation with unsaved edits displays the Unsaved Changes confirmation modal (`.unsaved-changes-modal`).
   - "Cancel" closes the modal, aborts navigation, and preserves modified inputs.
   - "Confirm" discards unsaved changes and proceeds with navigation.
4. **Controlled Error Handling**:
   - Handled missing/nonexistent plan IDs and out-of-range versions by rendering controlled error banners (`.plan-error-banner`) with user-friendly messages and an action to return to the planning list.
5. **Security & Immutability**:
   - Protected API route `/api/plans/:id` enforces tenant ownership: unauthorized tenant requests return HTTP 404/403.
   - Verified row-level D1 record immutability: historical plan versions and inputs remain unchanged.
