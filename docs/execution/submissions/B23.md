## Problem and change

User problem / evidence:
Visual audit V10 identified that cashflow tools (`/calculators/net-worth`, `/calculators/budget`, `/calculators/emergency-fund`) lacked consistent hierarchy, suffered from redundant framing (duplicate 3-card trust banner, bloated static FAQ sections pushing interactive controls down), and needed clear accounting labels for negative/deficit/coverage outcomes without relying on color alone. Furthermore, numeric inputs across cashflow tools needed explicit winning typography rules to guarantee 16px computed font-size.

Implementation:
1. Unified `NetWorthCalculator`, `BudgetCalculator`, and `EmergencyFundCalculator` inside `CashflowPlanningCalculator.tsx` using the standard header pattern with `<p className="calculator-scope-note">`.
2. Removed redundant `.compound-trust-strip` 3-card banner across all three cashflow calculators, moving interactive workspace inputs higher towards the fold (remediating V10).
3. Converted long static FAQ cards into native, collapsible `<details className="compound-analysis-card compound-faq-card">` with an accessible `<summary>`, collapsing secondary explanatory content by default to reduce mobile vertical bloat.
4. Added distinct accounting labels for negative, zero, and coverage outcomes without relying solely on red/green colors:
   - Net Worth: Shows "Estimated net deficit" and "Net deficit (liabilities exceed assets)" when liabilities exceed assets.
   - Budget: Shows "Monthly deficit" and "Monthly deficit (spending exceeds income)" when expenses exceed take-home pay.
   - Emergency Fund: Displays "Reserve target fully covered" with a "Fully funded" badge when liquid assets satisfy the target months.
5. Preserved distinction between unpopulated/blank fields and actual numerical zero in `moneyFormatter` by formatting non-finite / NaN values as `—` (em dash).
6. Ensured immediate hydration by restoring existing saved state directly into initial state for all three calculators.
7. Fixed typography in `src/styles.css` with explicit winning CSS rules (`.cashflow-planning-calculator input[type="number"], .cashflow-workspace input[type="number"]`, and selects) computing to 16px (1rem) font size and 1.5 line-height.
8. Retained all 17 progressive disclosures across the three tools (category breakdowns, asset allocation, liability details, tax and expense schedules, assumptions).
