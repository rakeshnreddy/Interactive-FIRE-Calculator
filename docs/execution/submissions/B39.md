## 4. API Parse-Error Parity & Call-Site Audit

### Call-Site Audit for `readApiJson`
The generic parsing helper `readApiJson` is used exclusively by:
1. `readFinancialAccountResponse` (`src/lib/api/accounts.ts`, line 365)
2. `readGoalResponse` (`src/lib/api/goals.ts`, line 257)

Other API callers have distinct error-handling requirements and retain their baseline implementations:
- `readSavedPlanResponse` (`src/lib/api/plans.ts`): Uses dedicated `PlanRequestError` with `response.status` for 409 concurrency conflicts.
- `readTransactionResponse` (`src/lib/api/transactions.ts`): Uses dedicated `body.error` extraction on non-OK responses.
- `readProfileResponse` (`src/lib/api/profile.ts`): Retains baseline direct parsing without `readApiJson`.
- `loadSavedCalculatorResults` / `createCalculatorResultRecord` (`src/lib/api/calculatorResults.ts`): Retains baseline idempotency key and response structure validation.

### Error Behavior Comparison (Baseline vs. Candidate)

| Scenario | Baseline Behavior | Reworked Candidate Behavior | Status |

| Non-OK status (401, 403, 404, 500) | Throws `new Error(errorMessage)` | Throws `new Error(errorMessage)` | **IDENTICAL** |
| 200 OK + malformed JSON (`'not json'`) | `await response.json()` throws `SyntaxError` | `await response.json()` throws `SyntaxError` | **IDENTICAL** |
| 200 OK + empty body (`''`) | `await response.json()` throws `SyntaxError` | `await response.json()` throws `SyntaxError` | **IDENTICAL** |
