## Problem and change

C07 screenshot evidence (`evidence/C07/remaining/import_result.png`) revealed 4 starting defects in the accounts presentation:
1. Native date input in `.balance-form` was restricted to 148px, crowding the date text against the native browser calendar picker icon.
2. Imported cents (e.g. 12345.67) were formatted with integer rounding ($12,346) in account cards and balance history.
3. The signed-in profile band rendered duplicate email lines when `displayName` was identical to `email`.
4. Platform routing status rendered developer implementation language ("Accounts route is wired.").

Implementation:
- Updated `.balance-form` CSS grid to `minmax(120px, 1fr) minmax(172px, 190px) auto 40px`, providing 190px width for native date controls across all viewports.
- Enhanced `formatCents` with explicit `{ minimumFractionDigits: 2, maximumFractionDigits: 2 }`, ensuring `$12,345.67` and `$2,500.00` are rendered in account cards and balance history.
- Added `isBalanceStale` rule computing UTC calendar-day difference (`> 30` days = stale), rendering `.account-stale-badge` (`Update due`) for balances needing review, with as-of dates rendered.
- Simplified `SignedInProfileBand` to suppress duplicate `<small>` email lines when `auth.user.email === auth.user.displayName`.
- Replaced routing language with user-facing copy: "Accounts and balances are active." on `/accounts` and "Dashboard overview is active." on `/dashboard`.
