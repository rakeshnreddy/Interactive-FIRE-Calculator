## 7. Plan Health Result-Presentation Correction & Reviewer Hardening
In response to reviewer feedback and Chrome 390px visual inspection, Plan health result presentation was corrected and hardened:
1. **Defect Root Cause**:
   - `calculateFirePlan` simulates both expense and portfolio modes. With `desiredFinalValue = 0`, both simulations naturally reach $0 at the final horizon year (`year === duration`), emitting `balance_depleted` warnings at year 30.
   - `normalizeWarning` extracted the raw engine code `balance_depleted` as the title, producing two duplicate cards with snake_case tokens.
   - In `planWarnings`, `averageRate('i') >= averageRate('r')` evaluated `0 >= 0` to true, triggering an `Inflation pressure` card even when both rates were 0.0%.
   - Together, these 3 low-quality cards crowded out meaningful, actionable financial checks (`Current portfolio drawdown`, `Funding gap`, and `High starting withdrawal`).
2. **Hardened Presentation Invariants in `src/App.tsx`**:
   - **Typed Engine Code Mapping**: Imported `PlanWarningCode` from `./lib/fire` and typed `ENGINE_WARNING_TITLES: Record<PlanWarningCode, string>`, aligning exactly with the exported union (`invalid_rate_period`, `unsupported_withdrawal_timing`, etc.). Fallback `humanizeWarningTitle` guarantees zero snake_case exposure anywhere in Plan health.
   - **Strict Numeric Horizon Depletion Invariant**: Dedicated predicate `shouldSuppressHorizonDepletion` requires:
     - `code === 'balance_depleted'`
     - `desiredFinalValue === 0` and `typeof duration === 'number'`
     - Numeric `year === duration` (early depletion is never suppressed)
     - Finite ending `warning.value` close to zero (`Math.abs(warning.value) <= 1.0` within solver tolerance)
     - Substantial negative balances (`Math.abs(endingBalance) > 1.0`) are strictly preserved
     - Unstructured message-text fallback was removed completely
   - **Mode Context & Deduplication**: Distinct simulation modes are labeled where applicable (`Target spend` vs `Current portfolio`), while duplicate identical notices within the same context are filtered via set deduplication.
   - **Inflation Pressure Threshold**: Updated check to `avgInflation > 0 && avgInflation >= avgReturn` so 0% inflation is not flagged as inflation pressure, while real inflation risk remains warned.
3. **Behavioral Test Coverage (`src/fireAssumptions.test.tsx` Test 9)**:
   - Failed first on previous code (`AssertionError: expected [ 'balance_depleted', …(3) ] to include 'Funding gap'`).
   - Verified that after the fix, clicking Calculate on the fresh baseline renders `Current portfolio drawdown` (depletion in year 10 for $750k portfolio at $80k spend), `Funding gap` ($1,650,000 separates portfolio from FIRE number), and `High starting withdrawal` (10.7% starting withdrawal rate).
   - Verified no raw codes (`balance_depleted`), no snake_case, no duplicate depletion notices, and no `Inflation pressure` on 0%/0% baseline.
   - Verified that genuine engine warnings (setting return to 16.0% and adding an out-of-range event in year 45) render with humanized plain-language titles (`High return assumption`, `Event outside timeline` / `Cash flow outside timeline`) and preserve full detailed messages.
4. **Risk Note & Safety Invariants**:
   - `src/lib/fire.ts` remains byte-identical; zero financial formulas or projection calculation engines were altered.
   - Warning suppression is strictly isolated to expected horizon depletion (`year === duration`) with zero estate target (`desiredFinalValue === 0`) and near-zero ending balance (`|balance| <= 1.0`). Early depletion (e.g. year 10) and non-zero estate target depletions are strictly preserved.
   - Full 7-stage verification suite confirms 100% test passage across all 55 test files (1685 passed, 0 failed) and clean isolated build (21 production assets).
