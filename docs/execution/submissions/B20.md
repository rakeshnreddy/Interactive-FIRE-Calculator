## Problem and change

User problem:
Generic calculators in `CalculatorLibrary` forced users on mobile devices to scroll through 4 repetitive context cards ("What it answers", "Why it matters", "How it fits", "How to read it") before reaching the first editable input. At a 390px mobile viewport, the first editable input was pushed down to $y \approx 1133\text{px}$ – $1207\text{px}$ (far below the fold). Furthermore, input helper text was hidden inside title-only hover tooltips on tiny dots, primary output metrics lacked distinct visual hierarchy over secondary metrics, and metric descriptions were inaccessible to keyboard and touch users without hover capabilities.

Implementation:
1. Reordered Layout and Hierarchy:
   - Preserved exact H1 (`#calculator-detail-title`) and added `<p className="calculator-scope-note">` for concise scope definition.
   - Relocated the 4 introductory context articles below the calculator grid into a dedicated `<section className="calculator-methodology-panel" aria-label="...">`.
   - On a 390px viewport, the first editable input now appears at $y = 456\text{px}$ – $516\text{px}$ (under the $650\text{px}$ threshold requirement).
2. Accessible Form Controls and Helper Text:
   - Added explicit `id` and `htmlFor` pairings to inputs and labels.
   - Replaced title-only tooltip dots in labels with visible `<small className="calculator-field-helper" id={helperId}>` positioned below each control and programmatically linked via `aria-describedby`.
3. Visually Dominant Primary Metric & Accessible Disclosures:
   - Designated the primary metric (`metrics[0]`) with `.calculator-result-metric-primary`, giving it full grid span (`1 / -1`) and larger typographic scale (`clamp(1.4rem, 2.6vw, 2.2rem)`).
   - Replaced title-only help dots in metrics with accessible native buttons `<button type="button" className="calculator-help-btn" aria-expanded={isHelpOpen} aria-controls={helpId}>`.
   - Clicking toggles the disclosure region `<p className="calculator-metric-help-text" id={helpId} role="region">`, preserving keyboard focus on the triggering button.
4. Preserved Scenarios and Responsive CSS:
   - Updated scenario buttons to include `.calculator-scenario-tab` with `aria-selected` tracking.
   - Extended responsive styling in `src/styles.css` across 1040px, 720px, 390px, and 320px breakpoints, ensuring solid surfaces, clean borders, and zero horizontal scroll overflow.
