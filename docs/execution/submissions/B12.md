## What was built
- **Schema (additive, migration 0009):** `analytics_consent` (user → random pseudonym, with tombstone triggers), `analytics_events` and `analytics_cohorts` keyed by pseudonym only. The Clerk user ID never enters an event row.
- **Event contract** (`src/lib/analytics.ts`, shared by browser and server): six allowlisted events with enumerated or slug-only properties. Amounts, free text, URLs, identifiers and unknown fields are rejected on both sides.
- **API:** `GET/PUT /api/analytics/consent`; `POST /api/analytics/events` requires consent (403 otherwise), accepts 1–20 events, de-duplicates by event id, caps 500 events per pseudonym per day (429), and stores the server's receipt day rather than the client clock. Body size is capped by the B41 middleware.
- **Server events:** `decision_saved` (starts the cohort) on plan and calculator-result saves; `review_completed` on a non-duplicate monthly review, updating W1/M1/M3 with the plan's ≥7-day returning-review rule. Both are no-ops without consent and never interrupt the product flow.
- **Retention:** raw events purged after 90 days, cohort membership after 120 days; matured-denominator report with suppression under 10.
- **Consent UI:** Settings → "Help improve FinPath" toggle, off by default, plain description of what is and is not collected; turning it off deletes collected records immediately. Account deletion purges all three tables.
- **Client:** events are queued only when consent is known to be on; while sign-in or the consent lookup is still resolving they are held, then sent or discarded. Signed-out visitors never queue anything.

- **Full suite:** exit 0, 2,440 tests.
- **Hosted `c11-analytics` on `f994eca`** ([report](../evidence/C11/hosted-smoke-c11-analytics-f994eca.json)), all 9 stages observed: a signed-out visitor calculating sends no analytics request; consent defaults to off and events without consent get 403; opting in through the real Settings toggle creates a pseudonym unrelated to the user id; a calculation produces one `calculation_completed` row whose props contain no amounts; a plan save records `decision_saved` and starts the cohort; opting out purges events, cohort and consent. Cleanup verified for both tenants.
- **Defects the hosted run found and fixed:** events dropped while the consent preference loaded (`e33846a`), events dropped while sign-in was still resolving (`d0ade7f`), and the app remounting when Clerk loaded lazily, which wiped the visitor's inputs (`f994eca`, with a regression test).
