# B38 submission — public delivery: route HTML, 404, performance, headers

Status: `ready_for_review` (Claude, owner takeover 2026-09-26; Codex accepts).
Code: `d01a0c4` plus `2292aee` (flat route files). Preview: `https://bbb7d3e6.interactive-fire-calculator.pages.dev` (deployment `bbb7d3e6-436c-4374-a251-277fc9631374`, preview D1).

## Baseline, re-measured before changing anything
- `main` was 574 KB raw, and Vite warned about chunk size.
- `@clerk/react`, `@clerk/shared` and `query-core` made up about 427 KB of main's sources, downloaded by every public visitor.
- The server HTML for every route had the homepage title.
- A `/* /index.html 200` catch-all made every unknown path return 200 and be indexable.
- There was no `_headers` file.

## Changes
- **Lazy Clerk** (`src/authRuntime.tsx`, `src/auth.tsx`):
  - **When it loads at start:** only on workspace routes, when a signed-in `__client_uat` cookie hint exists, or when the URL carries `__clerk_*` redirect parameters.
  - **Otherwise:** it loads on an explicit Sign in or Sign up click, which then completes (redirect to sign-in, or the sign-up modal).
  - **Button wrappers:** `SignInIntent`, `SignUpIntent`, `AccountUserButton` and `SignOutControl` replace the direct Clerk components in `App` and the three calculators.
  - **No false signed-out flash:** a signed-in hint shows "loading" instead.
- **Code splitting:**
  - The signed-in workspace panels (Dashboard, Transactions, Goals, Accounts, Profile and `PlatformPage`, about 1,880 lines) moved from `App.tsx` to `src/workspace/WorkspacePanels.tsx` and load lazily behind a Suspense loading state (PA-9). `App.tsx` is now 4,756 lines.
  - React and the calculator catalog are separate chunks that can be cached independently.
- **Prerender** (`scripts/prerender_routes.mjs`, runs after `vite build`):
  - Writes a route-specific title, description, canonical, robots tag, JSON-LD and a heading for all 85 sitemap routes (the test asserts the set equals the sitemap), plus 7 `noindex` workspace routes.
  - Uses flat `route.html` files. Directory `index.html` files made Pages add a trailing-slash 308 redirect, which the first hosted run caught.
- **404:** a static `404.html` with `noindex` (no app script, so the homepage never renders under an unknown URL). `_redirects` now only rewrites `/plans/* → /plans`.
- **`public/_headers`:**
  - **CSP:** no inline or eval scripts; only `'self'`, Clerk hosts and Cloudflare Turnstile are allowed; `frame-ancestors 'none'`; `object-src 'none'`.
  - **Other security headers:** HSTS, `nosniff`, `Referrer-Policy`, `X-Frame-Options: DENY` and `Permissions-Policy`.
  - **Caching:** immutable caching for hashed `/assets/*`.
  - **Inline styles:** allowed, because Clerk's components and React style attributes need them.

## Measurements (preview-auth build)
| Chunk | Before | After |
|---|---|---|
| main | 574 KB | **190 KB**, no Vite size warning |
| react-vendor | (in main) | 136 KB, cached independently |
| calculator-catalog | (in main) | 76 KB |
| Clerk | in main, always | 142 KB, **on demand only** |
| Workspace panels | in main | 44 KB, workspace routes only |

- **Initial JS for a public page:** about 402 KB raw, down from 574 KB. The Clerk runtime script (fetched from Clerk's host) is also no longer loaded.
- **Honest reading of the target:** the "< 250 KB main" goal is met partly by splitting out the vendor and catalog chunks. The real saving on first visit is about 30% of initial JS, plus removing Clerk entirely.
