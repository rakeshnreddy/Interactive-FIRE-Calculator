## Problem and change

User problem / evidence:
Visual audit V10 and V12 identified that the flagship FIRE calculator (`/calculators/fire`) lacked a unified scope note, suffered from accessible name bloat where long tooltip helper text was repeated inside input accessible names due to nesting interactive elements and helper text inside `<label>`, lacked explicit `aria-describedby` associations, and lacked clear stale-result indication when users modified inputs after calculating, risking confusion where users might mistake a previous result for current inputs.

Subsequent review C05 identified three specific defects in the submitted candidate:
- **R1**: Repeated period controls in `Field` generated duplicate IDs (`field-years`, `field-annual-return`, etc.), causing the second "Years" label to focus the first period input.
- **R2**: `src/styles.css` forced tooltip visibility on `:focus-within` and `:hover`, causing `aria-expanded=false` to conflict with visual `opacity: 1` when tabbing or pressing Enter twice.
- **R3**: Changing inputs (such as withdrawal timing) after calculating created an inconsistent boundary where projection rows stayed snapshotted but the timing pill and scenario comparisons evaluated live draft inputs.

Implementation:
1. Unified the header framing using `<p className="calculator-scope-note">` ("Answer one retirement planning question at a time. Plan retirement portfolio targets or test sustainable annual withdrawals across customizable inflation and market regimes.") (remediating V10).
2. Refactored `Field` and `InfoTip` in `src/App.tsx`:
   - Separated `<label htmlFor={id}>` containing exclusively concise accessible names ("Current age", "Retirement age", "Plan end age", "Annual withdrawal need", "Current portfolio") from the helper tooltip.
   - **R1 Repair**: Replaced label-derived fallback in `Field` with React 18 `useId()`:
     ```tsx
     const autoId = useId().replace(/[^a-zA-Z0-9_-]/g, '_');
     const resolvedId = childId || (id ? id : `field-${fieldSlugify(label || 'input')}-${autoId}`);
     ```
     Preserved explicit child/caller IDs while ensuring 0 duplicate IDs across multi-period inputs, recurring rows, and scenario fields. Clicking the second "Years" label activates the second period input.
   - **R2 Repair**: Reconciled disclosure state onto `isOpen` as the single source of truth. Removed `.info-tip:hover .info-popover` and `.info-tip:focus-within .info-popover` from `src/styles.css`. Popover visibility is controlled via `.is-visible` matching `aria-expanded={isOpen}`. Enter/Space toggles, Escape closes while preserving trigger focus, and closed help computes to `opacity: 0` even when focused.
   - Associated helper text via `aria-describedby` pointing to `${id}-help` on the input control (remediating V12).
   - Replaced focusable `<span>` info-tips with accessible native `<button type="button" className="info-dot" aria-expanded={isOpen} aria-label={`Help for ${label}`}>` controls located outside the HTML `<label>`.
   - Added explicit unit indicators: currency prefix `$` on withdrawal need and portfolio balances, and duration suffix `years` on timeline age inputs via `.calculator-input-control`.
3. Defined clear stale-result state management after input changes (**R3 Repair**):
   - When inputs change after a calculation, the previous result remains visible for reference rather than vanishing abruptly, decorated with `is-stale` class and a visible notice: `<div className="stale-result-badge" role="status" aria-live="polite">` ("Inputs changed since last calculation. Click Calculate to update results.").
   - Connected withdrawal timing pill to `activePlanForDisplay.withdrawalTiming` (`{activePlanForDisplay.withdrawalTiming === 'start' ? 'Start-year' : 'End-year'}`) rather than live draft inputs.
   - Connected `comparisonRows` to evaluate scenarios against `activePlanForDisplay` and `activeResultForDisplay`.
   - The primary action button transitions to "Recalculate". Clicking "Recalculate" computes fresh results with current inputs and clears the stale badge across all panels.
4. Preserved both FIRE planning modes ("FIRE number" and "Withdrawal") and all advanced assumption modules (`<details className="advanced-shell">` for model options, multi-period rates, one-off events, recurring income and expenses, and 3-way scenario comparisons). `src/lib/fire.ts` remains frozen and untouched.
5. In `src/styles.css`:
   - Added accessible button styling for `button.info-dot`.
   - Added `.hero-result.is-stale` and `.stale-result-badge` styling.
   - Enforced 16px font-size and 1.5 line-height across `.core-fire-form input[type="number"]` and `.quick-calculator input[type="number"]`.
