## Problem and change

Public and missing-config visitors previously saw private Dashboard, Transactions, and Goals destinations first. Mobile navigation controls were buttons rather than real links, the disclosure ignored Escape, and route handlers unconditionally prevented modifier/middle-click behavior. Desktop Workspace also used application-menu roles for ordinary links.

B17 adds a tested auth-aware navigation model, promotes public Calculators and FIRE links for every non-signed-in state, keeps account routes in a labeled Workspace disclosure, and converts route controls to anchors with real `href`s. Only an unmodified primary click is intercepted for the SPA. Desktop/mobile disclosures close on Escape with focus return; mobile also closes on route change and desktop breakpoint transition. Selected routes expose `aria-current`; the theme toggle exposes action/pressed state; the skip link targets a focusable main region; lazy route headings receive focus once without later stealing editing focus. The B16 R1 follow-up changes only dropdown styling and preserves all B17 behavior.

Changed implementation/test files: `src/App.tsx`, `src/styles.css`, `src/lib/navigation.ts`, and `src/lib/navigation.test.ts`. No routing framework, dependency, auth bypass, formula, API, data, analytics, or production fixture was added.
