**Transparency:** commit `5cd3073` was pushed while one fixture test was failing. The test typed into the deletion field in a way React never registered. `e999b52` fixed it, and every commit since has been gated on a green suite.

## Changes
- **PA-9:** the privacy panel moved to `src/settings/PrivacyControlsPanel.tsx`; `App` re-exports it for the fixtures.
- **Plain language:** no "D1" or "Clerk" in user-facing copy (also removed from the Settings page summary). The copy matches `docs/DATA_DELETION_AND_RECOVERY.md`:
  - **Deleted:** all saved FinPath records, plus drafts saved in this browser.
  - **Not deleted:** the sign-in account, drafts on other devices, request logs, and encrypted backups, which expire on their normal schedule.
  - **After deletion:** you stay signed in, and new saves start from an empty account.
- **Server-confirmed outcomes** (`src/settings/privacyOutcome.ts`):
  - Success is reported only when the server returns `localAccountDataDeleted: true`, with the real record count taken from `deletedRows`.
  - The message never describes the sign-in account as deleted.
  - Failures explain that nothing was marked as deleted and that the user can try again. The typed confirmation is kept on failure.
- **States:**
  - Export and delete are both disabled while either request runs, so no duplicate destructive submit is possible.
  - The form submits only with the exact confirmation phrase.
  - Errors use `role=alert`; progress uses `role=status`.
  - Focus moves to the outcome message.
