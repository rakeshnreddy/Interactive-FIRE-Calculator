## Problem and change

Task B04 establishes atomic, retry-safe calculator result saving and downstream entity creation. Previously, downstream draft creation (e.g. `createGoal`, `createAccount`, `createPlanDraft`) was executed in separate database queries prior to inserting `saved_calculator_results`. If a network interruption or database failure occurred mid-flight, orphan goals or accounts remained in the database. Furthermore, retry requests could generate duplicate records, and conflicting payloads with identical keys were not guarded against.

Implemented changes:
1. **Additive Schema Migration (`migrations/0005_saved_calculator_idempotency.sql`)**:
   - Added `idempotency_key TEXT` and `payload_hash TEXT` columns to `saved_calculator_results`.
   - Created partial unique index `idx_saved_calculator_results_user_idempotency` on `(user_id, idempotency_key) WHERE idempotency_key IS NOT NULL` scoped strictly to `user_id`.
2. **Deterministic Canonical Payload Hashing (`hashCalculatorPayload`)**:
   - Implemented canonical JSON stringification sorting `inputValues` keys, `result.metrics` by label, and `result.assumptions` alphabetically.
   - Computes SHA-256 digest using standard Web Crypto API (`crypto.subtle.digest`).
3. **Atomic Single-Batch Destination + Result Persistence (`createSavedCalculatorResult`)**:
   - Bundles destination insert statements (`goals`, `financial_accounts`, `account_balances`, or `plans`) and `saved_calculator_results` insert into a single `database.batch(...)` transaction.
   - Any failure or abort rolls back the entire batch, eliminating orphan entities completely.
4. **Idempotent Retry Resolution (`CALCULATOR_SAVE_STATUS`)**:
   - Checks for existing `(user_id, idempotency_key)` before and upon catching unique constraint races.
   - If payload hash matches: reads existing entity and returns `{ createdEntity, savedResult, saveStatus: 'retry' }` with HTTP 200.
   - If payload hash differs: throws `IdempotencyConflictError` and returns HTTP 409 with `{ code: 'IDEMPOTENCY_CONFLICT' }`.
5. **Multi-Tenant Isolation**:
   - Unique constraints and lookups are strictly scoped to `user_id`. Foreign users utilizing identical idempotency keys create independent records without collision or data leakage.
6. **Transaction Destination Guard**:
   - Saving to `conversionRoute: '/transactions'` creates `saved_calculator_results` with `created_entity_type: null` and creates zero fake rows in `transactions`.
7. **Client Save Integration (`src/App.tsx`)**:
   - `createCalculatorResultRecord` generates unique `idempotencyKey = crypto.randomUUID()` and supplies it in the payload and `Idempotency-Key` HTTP header.
   - Updated `SavedCalculatorResult` and `CalculatorSaveApiResponse` types to include `idempotencyKey`, `payloadHash`, and `saveStatus`.
8. **Real SQLite D1 Integration Test Suite (`src/calculatorResults.test.ts`)**:
   - Implemented in-memory SQLite D1 harness using Node's `DatabaseSync` running migrations 0001 through 0005.
   - Validated atomicity rollback on injected failure (zero orphans), identical retry resolution, 409 conflict, multi-tenant isolation, concurrency race handling, and transaction destination integrity.
