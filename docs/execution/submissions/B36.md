# B36 submission — FIRE answers "when can I retire?"

Status: `ready_for_review`. Implemented by Claude under the 2026-09-26 owner takeover amendment. Codex runs the independent review, including the formula review OD-2 requires.
Code commit: `a8f74222b89e46feafcd8f85561457f48dc3add5`. Preview: `https://f7bbfd7c.interactive-fire-calculator.pages.dev` (deployment `f7bbfd7c-7c39-444b-b022-804887850074`, preview D1).

## What changed, by requirement

- **OD-1: empty, required rates.**
  - Return and inflation now sit in the core form, start empty, and must be filled before a result appears. The Calculate button is disabled and explains why.
  - Blank fields show a hint, not an error. Errors appear only for invalid values.
  - "Use example values" applies the homepage's `HERO_FIRE_FIXTURE` rates (7% / 2.5%), labelled as illustrative assumptions rather than forecasts or historical averages. No historical-performance claim is made, so no citation is needed.
  - A deliberate 0% is valid.
  - The Advanced summary says "Return and inflation not set yet" until both rates are entered.
  - B35's no-injected-cash-flows rule is unchanged.
- **OD-2: additive accumulation engine** (`src/lib/fireAccumulation.ts`). The contract is written at the top of the file:
  - **Units:** today's money, using the real return (1+r)/(1+i)−1.
  - **Timing:** the balance is checked at the start of each age; each year's deposit is added at the end of that year.
  - **Savings growth:** optional, in real terms.
  - **Stopping rule:** the first whole age where the balance is at least the drawdown engine's `requiredPortfolio` for the horizon from that age to the plan end age. Rate periods are trimmed or extended to that horizon by `fitRatePeriods`.
  - **Otherwise:** the result is `not-reached`.
  - **Rates used:** accumulation uses period 1's rates, and the UI says so when there are several periods.
  - **Goldens:** five cases computed by hand in closed form (`src/lib/fireAccumulation.test.ts`):
    - normal case, retiring at 53, checked against a geometric-series balance
    - explicit 0% rates, retiring at 56
    - already financially independent
    - never reaches the target
    - savings growing 10% a year, retiring at 61
  - **Helpers:** `realReturn` (Fisher equation), `fitRatePeriods`, `projectPortfolioAtAge`.
  - **fire.ts:** the only change is `formatMoney`'s locale selection for INR; the drawdown functions are unchanged. All existing `fire.test.ts` goldens pass untouched.
- **Answer** (`src/components/FireRetirementEstimate.tsx`):
  - Headline "Retire at about age X", or "already covers", or "Not reached before age N". Without savings entered, it prompts for savings instead of inventing an age.
  - A driver sentence explaining the result.
  - A check at the chosen retirement age ("on track" or "short by …").
  - The rates actually used, plus the real rate, next to the answer, with today's-money and not-a-promise wording.
  - A savings-path table by age as the text alternative.
- **Validation** (`src/lib/fireValidation.ts`, 6 tests).
  - These withhold the result and block saving:
    - blank spending (no longer silently 0), negative spending, or 0 spending in FIRE-number mode
    - whole ages 0–120 in the right order
    - return between −50% and 50%, inflation between −10% and 30%
    - non-negative savings, and savings growth between −20% and 30%
  - Saving is blocked in both the calculator and the Planning Workspace while fields are invalid.
- **Stale results:** B24/B35's explicit Calculate model is kept (B36 allows "recalculate live or make stale unmistakable"). The stale badge now reads "Select Recalculate to update it".
- **Layout:**
  - The answer sits directly under the inputs.
  - The "Save and move plans" panel moved below the results, so the chart follows the answer.
  - Chart and table are labelled by age (year 1 = retirement age) with compact money ($1.4M, ₹20.4 L).
- **Currency:**
  - USD/INR switch for FIRE; the choice is saved in the snapshot.
  - Shared rule `resolveMoneyLocale`: INR uses `en-IN` unless the user picked a number format. This fixes the audit's ₹113,669 case, now ₹1,13,669, in `formatMoney`, `formatStoredCurrency`, the calculator library, and the compound interest, savings and cash-flow calculators.
  - `formatCompactMoney` produces L/Cr and K/M/B.
  - Two older tests that asserted Western INR grouping were updated to Indian grouping.
- **Saved plans:**
  - `accumulation` and `currency` are optional snapshot fields; server storage is free-form JSON, so no migration is needed.
  - All four load paths go through one `hydrateFromSnapshot`, and loaded plans show their stored rates.
  - The test "pre-B36 saved plan loads with its stored rates" covers this.
  - Rollback: revert the commit; old and new snapshots stay readable.
- **Copy:** the depletion warning now reads "If withdrawals started now … with no further savings …", so it no longer contradicts the retirement-age answer.
- **PA-9 narrow opt-out:** the roughly 900-line FIRE region shares about 60 root state hooks. New UI went into focused modules (engine, validation, money, answer component) and the load paths were consolidated. Moving the rest of the region needs a state reducer, which is outside B36 and should be its own refactor task.
