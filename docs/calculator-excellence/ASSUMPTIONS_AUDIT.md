## 2. Table Legend & Compact Notation Guide

To ensure high information density and strict maintainability, the inventory table uses standardized codes:

| Field | Code | Meaning |
|---|---|---|
| **Region** | `GL` | Global (multi-currency, currency agnostic, or USD default) |
| | `IN` | India regional (INR default currency, Indian financial conventions) |
| | `US` | United States regional (USD default currency, US federal/state conventions) |
| **Family** | `BOR` | Borrowing & Loans (mortgages, personal/auto loans, APR, payoff, amortization) |
| | `INV` | Investing & Wealth Accumulation (compound interest, SIP, mutual funds, CAGR, ROI) |
| | `PLN` | Financial Planning & Retirement (FIRE, retirement, net worth, budget, emergency fund) |
| | `SAV` | Cash Savings & Term Deposits (FD, RD, CD, HYSA) |
| | `TAX` | Tax, Withholding & Payroll (income tax, paycheck, salary, GST, TDS, capital gains) |
| **Value Provenance** | `EX` | Nonzero inputs represent illustrative starting examples in source, not legal defaults or advice |
| | `REQ` | Input value is required for calculation; zero causes zero output or invalid state |
| | `BASE-0` | Clean zero baseline in source; feature defaults to zero (e.g. extra payments, top-ups, growth rates) |
| **Trigger** | `REACT` | Reactive: recalculates synchronously on input change via React `useMemo` |
| | `EXPL` | Explicit: requires user to click an action button (`Calculate` / `Recalculate`) |
| **Control Placement** | `FLAT` | Flat form: all inputs rendered in a single standard grid |
| | `COLL-OPT` | Collapsible Options: optional inputs (`annualTopUp`, extra payments) placed in `<details>` under standard inputs |
| | `COLL-PRE` | Collapsible Pre-Button: advanced options in `<details>` placed *before* the explicit calculate button |
| | `SPEC-ACC` | Specialized Architecture: custom tabs, scenario pickers, and accordion panels in dedicated component |
| **Disposition** | `LOW` | Transparent formula, clear assumptions, minimal drift or misinterpretation risk |
| | `MED` | Omitted secondary frictions, unstated constant rates, or potential interim typing jitter |
| | `HIGH` | Significant unstated economic assumptions (e.g. SORR in SWP, static tax tables, friction omission) |

## 4. Source-Backed Deep-Dive Findings & Cross-Suite Vulnerabilities

### A. Sequence-of-Returns Risk (SORR) Omission in Drawdown Models
- **Source Inspection Evidence:** In `src/lib/seoCalculators.ts:1505–1522` (`withdrawalRunway`), the SWP calculation deterministically projects balance using a constant monthly yield:
  ```typescript
  while (currentBalance > 0 && months < 1200) {
    currentBalance = currentBalance * (1 + monthlyRate) - withdrawal;
    months += 1;
    if (currentBalance > 0 && monthlyRate >= 0 && currentBalance * monthlyRate >= withdrawal) {
      return { endingBalance: currentBalance, months: 1200 };
    }
  }
  ```
- **Finding:** Applying a static 7.0% annual return ($0.583\%$ monthly) ignores sequence-of-returns risk. If market losses occur in early years of drawdown, capital depletes dramatically faster than projected.
- **Risk Level:** **HIGH RISK**. Users planning retirement cash flows may assume guaranteed longevity based on a static deterministic curve.
- **Remediation Requirement:** Maintain the core formula math as a baseline, but introduce clear visual disclosures explaining that actual portfolio longevity is sensitive to early-year return volatility.

### B. Statutory Scheme Assumption Provenance (PPF & EPF)
- **Repository Source Facts:**
  1. **PPF (`src/lib/seoCalculators.ts:390`):** Pre-filled with an illustrative default rate of `7.1%` and a 15-year tenure.
  2. **EPF (`src/lib/seoCalculators.ts:391, 145`):** Does not define a dedicated scheme-specific rate; it imports the generic `termInputs` array, which defaults to `8%` and 10 years.
  3. **Formula Behavior (`src/lib/seoCalculators.ts:1016–1033`):** PPF calculates an annuity due compound value ($P \times [((1+r)^n - 1)/r] \times (1+r)$); EPF compounds employee plus employer monthly contributions at $r/12$ without modeling statutory pension allocations (such as EPS diversion, which is unmodeled in source and requires official-source verification).
- **Finding & Correction:** External statutory governance processes, revision cadences, and official effective dates are not established in the repository source code and require separate primary-source verification. The application must not render speculative badges (such as synthetic effective quarters) or claim real-time gazette synchronization. All rates must be presented strictly as user-adjustable illustrative examples for educational planning, not official legal rates or personalized advice.

### C. Borrowing Suite: Accurate Demarcation of Friction Costs & Escrow
- **Source Inspection Fact:** The repository already provides dedicated calculators with comprehensive friction modeling:
  - `closing-costs` (`seoCalculators.ts:426`, `696–705`): Calculates upfront closing costs and total cash to close.
  - `escrow` (`seoCalculators.ts:427`, `719–729`): Calculates monthly property tax, insurance, and HOA reserves.
  - `pmi` (`seoCalculators.ts:479`, `1073–1079`): Models private mortgage insurance based on down payment and loan-to-value.
  - `apr` (`seoCalculators.ts:430`, `662–671`, `1330–1349`): Uses an iterative binary search to solve for APR including finance charges/closing costs.
  - `mortgage-refinance` & `mortgage-points` (`seoCalculators.ts:415, 421`): Factor in closing costs and upfront points.
  - `fha-loan` & `va-loan` (`seoCalculators.ts:432–433`): Model upfront and annual MIP and VA funding fees.
- **Finding:** The actual deficiency is restricted to standalone base loan/mortgage calculators (`mortgage`, `emi`, `auto-loan`, `personal-loan`) which compute pure Principal & Interest ($P \times r / (1 - (1+r)^{-n})$) without providing an optional integrated toggle or direct cross-links to companion escrow and closing-cost tools.

### D. Execution & Interaction Alignment: Keystroke Reactivity vs Explicit Calculation
- **Source Inspection Evidence:**
  - **Flagship FIRE Calculator (`src/App.tsx:8328–8342`):** Requires clicking an explicit `Calculate` or `Recalculate` button (`calculateNow`). Modifying inputs sets `isStale = true`, which displays a warning badge: *"Inputs changed since last calculation. Click Calculate to update results."*
  - **Generic SEO Calculators (`src/CalculatorLibrary.tsx:474`):** Use a pure reactive loop:
    ```typescript
    const result = useMemo(() => calculateSeoCalculator(calculator, scenarioValues), [calculator, scenarioValues]);
    ```
- **Finding:** While pure reactivity provides instant feedback on simple calculators (e.g. `rule-of-72`), rapid typing on multi-digit numbers or amortization schedules triggers continuous recalculation and renders interim fractional states. Debouncing inputs or introducing calculation awareness prevents visual jitter.
